# Integration points — credigit-ser-landing

Every connector point of the marketing site. The site is a static export on Netlify with no server code, so it has no
Connectors framework of its own; each point below is either a browser call, a hosting-platform feature configured in
the Netlify UI, or a link. When a Credigit receiver exists, demo requests should move behind the core backend's
Connectors framework (open question SITE-Q-01).

| # | Connector / system | Direction | Mode | Trigger | Payload / contract | Owning module | Configuration | Status |
|---|---|---|---|---|---|---|---|---|
| IP-01 | Netlify Forms — `demo-request` form | Outbound (browser → Netlify) | Real-time | Visitor submits the demo form (`netlify-forms` transport) | `POST /__forms.html`, `Content-Type: application/x-www-form-urlencoded`. Fields: `form-name=demo-request`, `bot-field` (honeypot, empty), `name`, `email`, `institution`, `institutionType` (`bank` \| `mfi` \| `other`), `role`, `country`, `message`, `source=credigit-ser-landing`. Response 2xx = stored. Detection contract: `public/__forms.html` (`data-netlify="true"`, `netlify-honeypot="bot-field"`) must declare every field | `site` (`src/lib/demo-request.ts`, `src/sections/demo-request-form.tsx`) | `NEXT_PUBLIC_DEMO_REQUEST_TRANSPORT=netlify-forms` (`netlify.toml`); Netlify UI → Forms → enable form detection | Built |
| IP-02 | Netlify Forms → form notification e-mail | Outbound (Netlify → mailbox) | Real-time | Verified (non-spam) submission | Netlify's notification e-mail with all fields | `site` (hosting configuration) | Netlify UI → Site configuration → Notifications → Form submission notifications → Email notification (recipient set by owner) | To configure in Netlify UI |
| IP-03 | Netlify Forms → outgoing webhook (event point) | Outbound (Netlify → external system, e.g. CRM or core backend) | Real-time | Verified submission | Netlify submission JSON (`form_name`, `data{…fields}`, `created_at`, …) | `site` (hosting configuration) | Netlify UI → Form submission notifications → Outgoing webhook (URL of the subscriber) | Available, not configured |
| IP-04 | Netlify Forms — submissions export / API (inbound read) | Inbound (external system pulls from Netlify) | Batch / on demand | Sales or an integration reads submissions | Netlify UI CSV export, or Netlify API `GET /api/v1/forms/{form_id}/submissions` with a Netlify personal access token held by the consumer (never in this repo) | `site` (hosting) | Netlify account | Available |
| IP-05 | JSON demo-request receiver (future core backend / CRM) | Outbound (browser → receiver) | Real-time | Visitor submits the demo form (`json` transport) | `POST <NEXT_PUBLIC_DEMO_REQUEST_ENDPOINT>`, `Content-Type: application/json`, body `{name, email, institution, institutionType, role, country, message, source}`. Receiver must rate-limit and bot-protect (public URL) | `site` (`src/lib/demo-request.ts`) | `NEXT_PUBLIC_DEMO_REQUEST_TRANSPORT=json`, `NEXT_PUBLIC_DEMO_REQUEST_ENDPOINT` | Supported, no receiver (SITE-Q-01) |
| IP-06 | Core application (credigit-ser-frontend) | Outbound link | Real-time (navigation) | Visitor clicks Log in / Register | URL only: `<NEXT_PUBLIC_APP_URL>/` and `<NEXT_PUBLIC_APP_URL>/register/`; unset = local `/login/`, `/register/` placeholders | `site` (`src/content/site.ts` `authLinks`) | `NEXT_PUBLIC_APP_URL` (Netlify environment variable) | Built (paths: SITE-Q-04) |
| IP-07 | `@credigit/web-ui` (GitHub `develop`) | Inbound, build time | Batch (`npm install`) | Build | Library source; commit pinned in `package-lock.json` | `site` | `package.json` | Built |
| IP-08 | Google Fonts (Baloo 2, via library styles) | Outbound (browser) | Real-time | Page load | Font CSS / files | `@credigit/web-ui` | Library | Built |
